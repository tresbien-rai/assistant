## 2. What shipped

**Streaming actually streams (TS-01…TS-05).** `/api/chat/stream` used to run the
tool loop NON-streaming and emit the whole answer as one synthetic chunk; the
real stream path was only reachable with zero tools advertised, and the
scratchpad auto-armed, so nearly every send took the non-streaming branch. Both
providers now stream every round via `streamRaw`, so pre-tool narration is
visible instead of discarded, and tool cards render inline at the point they ran
(`textOffset` on the attachment, converted between live and stored coordinate
spaces — see the comments in `send.js`/`thread.js` before touching it).

**Session state (SS-01…SS-04).** `docs/SESSION_STATE_DESIGN.md` is the reference.
The model is now told what exists AND what does not; the scratchpad is on by
default; tool descriptions no longer assert containers that may not exist; both
edit tools plus `write_scratchpad` report before → after deltas.

**UI.** One field/checkbox appearance app-wide (`styles/base.css`), one
resizable-textarea treatment, inline tool cards stack rather than scrolling
sideways, and streaming no longer fights the user's scroll.

## 4. Open threads

**The ghost file — unresolved, deliberately parked.** A file
(`ode_to_tomatoes.txt`, 319 B, downloads scope) appeared in `list_files` that the
tester says they never created; it existed only in the scratchpad. Not
reproducible locally — **every file table in the local dev DB is empty**, so it
lives in the deployed environment.

What was ruled out by reading the code: `scratchpad.js` imports only config,
dal, diff, format and logger — it never touches Drive or any file store, and
every write into the downloads scope goes through `writeContentToStore`, whose
only callers are `create_file`, `edit_file`, the re-roll rollback, and
user-initiated saves. **There is no implicit scratchpad-to-file path.** So it was
an explicit tool call or predates the session. The 319 B is consistent with an
early short draft rather than the finished poem.

To settle it, `file_revisions` records `author`/`op`/`turn` per write:

```sql
SELECT r.author, r.op, r.turn, r.created_at, f.filename
FROM file_revisions r JOIN user_files f ON f.id = r.file_id
WHERE f.filename LIKE '%tomato%' ORDER BY r.created_at;
```

A model-authored row with a turn number closes it. **Rows absent while the file
exists is a real bug** and should be escalated.

**File digests (§7 of the design doc), specified but not built.** Three tiers
that compose: deterministic first-line/heading as a free floor; the model
writing a summary while it already has the content (a `summary` param on
create/edit, plus a batched `describe_files` for files injected by FC-03B); and
an aux model last. Provenance tagging (`authored` / `auto` / `none`) is the
load-bearing piece and should ship with tier 1. Tier 3 belongs with the eventual
global memory system rather than the file tools — store digests with
author/provenance/timestamp from day one so that system inherits something it
can reason about.

**Also outstanding:** prompt caching (none exists — no `cache_control` anywhere
in `server/src/`; §5 of the design doc covers the block split it would justify);
CF-02b (PDFs as working files); and `test-apiKeys-http.js`, which fails on clean
`main` because it needs a live server on `:3000` — a pre-existing integration
test, not a regression.

## 5. Gotchas worth knowing

- **Do not rewrite whole files with scripts.** A Python rewrite of `chat.css`
  normalised CRLF→LF across the file and put 2,700 lines of noise in one commit
  for a 3-line change. The Edit tool preserves line endings; use it.
- **`normalizeBlocks` appends missing preset blocks deliberately.** Slotting them
  in at their built-in index was tried and reverted: it breaks the stronger
  guarantee that the user's explicit order wins. `test-presets` catches it.
- **A test that accepts two shapes cannot detect a shape error.** The Gemini
  round-separator bug passed its first test because the test read the streamed
  text through either provider's shape. Both streaming tests now read only
  through their own.
- The scratchpad `state` preset block is **position-only and cannot be disabled**;
  the composer handles it above the enabled check so an already-stored
  `enabled:false` is ignored rather than obeyed.
